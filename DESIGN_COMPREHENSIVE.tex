\section{Purpose}

The HFT Market Simulator is a real-time distributed trading platform for evaluating algorithmic trading agents across multiple programming languages (Python, Rust, Go, C++). It provides:

\begin{itemize}
    \item \textbf{Automated Containerization}: Compile and sandbox polyglot submissions without manual intervention
    \item \textbf{Low-Latency Matching}: Native C++ exchange engine with sub-microsecond matching
    \item \textbf{Distributed Evaluation}: Kubernetes-based isolation ensuring contestant code cannot escape sandbox
    \item \textbf{Live Telemetry}: Real-time scoring, latency analytics, and order book visualization
    \item \textbf{Fair Competition}: Deterministic scoring based on throughput (TPS) and latency (P99)
\end{itemize}

\section{System Layers}

The system is organized into seven distinct layers:

\begin{enumerate}
    \item \textbf{Browser / UI Layer}: React + Vite frontend (port 5173)
    \item \textbf{API Gateway}: FastAPI telemetry service (port 8000)
    \item \textbf{Orchestration}: K8s lifecycle management and Docker builds
    \item \textbf{Data Stores}: Redis, Kafka, Zookeeper
    \item \textbf{Evaluation Sandbox}: Minikube/K8s with NetworkPolicy isolation
    \item \textbf{Matching Engine}: C++ low-latency exchange (port 8080)
    \item \textbf{Scoring Engine}: Python Kafka consumer and telemetry processor
\end{enumerate}

\section{Request Lifecycle: From Submission to Score}

The complete journey of an order from submission through execution to leaderboard display follows these stages:

\subsection{Stage 1: User Submission (T+0s to T+2s)}

\begin{enumerate}
    \item User opens \texttt{http://localhost:5173} in browser
    \item Browser loads React SPA, fetches initial leaderboard snapshot
    \item Browser opens Server-Sent Events (SSE) stream for real-time updates
    \item User selects submission ZIP and enters contestant ID
    \item Browser sends \texttt{POST /api/v1/submissions/upload}
    \item API extracts ZIP, validates structure, returns \texttt{\{status: "QUEUED"\}}
\end{enumerate}

\subsection{Stage 2: Orchestration (T+3s to T+6s)}

The orchestrator subprocess handles compilation and pod creation:

\begin{itemize}
    \item Loads Kubernetes configuration
    \item Creates \texttt{evaluation-sandbox} namespace
    \item Applies NetworkPolicy restricting egress to port 8080 only
    \item Auto-detects contestant language (Python/Rust/Go/C++)
    \item Generates language-specific Dockerfile
    \item Builds container image
    \item Creates Kubernetes pod specification with security constraints
\end{itemize}

\subsection{Stage 3: Trade Execution Flow (T+8s onward)}

\begin{lstlisting}[language=python]
# Bot submits order
t0 = time.time_ns()  # Bot-side timestamp
order_bytes = struct.pack("<QQdIB3x",
    order_id, t0, price, qty, side)

    setRows(JSON.parse(event.data))

    return "cpp"

\section{Kernel Tracepoint Hooks}

\begin{lstlisting}[language=c]
// Trace point: tcp_cleanup_rbuf (ingress)
TRACEPOINT_PROBE(tcp, tcp_cleanup_rbuf) {
    struct sock *sk = (struct sock *)args->skaddr;
    u16 dport = args->dport;

    if (dport != 8080) return 0;

    u64 ts = bpf_ktime_get_ns();
    u64 order_id = 0;

    order_timestamps.update(&order_id, &ts);
    return 0;
}

// Trace point: tcp_transmit_skb (egress)
TRACEPOINT_PROBE(tcp, tcp_transmit_skb) {
    u64 ts = bpf_ktime_get_ns();
    u64 order_id = 0;

    u64 *t_arrival = order_timestamps.lookup(&order_id);
    if (!t_arrival) return 0;

    struct order_event ev = {
        .order_id = order_id,
        .t_arrival = *t_arrival,
        .t_match_complete = ts,
        .engine_latency_ns = ts - *t_arrival,
    };

    latency_events.perf_submit(args, &ev, sizeof(ev));
    return 0;
}
\end{lstlisting}

\section{Correctness Validation}

Every trade is validated against the protocol contract:

\begin{lstlisting}[language=python]
class ContestantState:
    def validate(self, event: TradeEvent) -> bool:
        """Check all correctness invariants"""

        checks = [
            (event.match_id == self.last_match_id + 1,
             f"Sequence gap"),

            (event.t2_ns >= self.last_t2_ns,
             f"Clock went backwards"),

            (event.buy_order_id != event.sell_order_id,
             f"Self-match"),

            (event.t1_ns >= event.t0_ns and
             event.t2_ns >= event.t1_ns,
             f"Timestamp ordering violated"),

            (event.price > 0 and isfinite(event.price),
             f"Invalid price"),

            (event.qty > 0,
             f"Invalid quantity"),
        ]

        for condition, error_msg in checks:
            if not condition:
                self.correctness_error = error_msg
                return False

        return True
\end{lstlisting}

\section{Latency Percentiles}

\begin{lstlisting}[language=python]
def compute_percentiles(samples: List[Tuple[float, int]]) -> Dict:
    """Compute P50, P90, P99 from engine latency samples"""

    if not samples:
        return {"p50": 0, "p90": 0, "p99": 0}

    latencies_us = sorted([ns // 1000 for _, ns in samples])

    def percentile(data, p):
        idx = int(len(data) * p)
        return data[min(idx, len(data) - 1)]

    return {
        "p50": percentile(latencies_us, 0.50),
        "p90": percentile(latencies_us, 0.90),
        "p99": percentile(latencies_us, 0.99),
    }
\end{lstlisting}

\section{Disqualification}

A single validation failure is fatal:

async def leaderboard_stream():
    """Async generator for SSE streaming"""

    pubsub = await redis_client.pubsub()
    await pubsub.subscribe("leaderboard_updates")

    snapshot = await read_leaderboard()
    yield f"event: snapshot\ndata: {json.dumps(snapshot)}\n\n"

    timeout = 0
    try:
        while True:
            message = await pubsub.get_message(timeout=1.0)

            if message:
                leaderboard = await read_leaderboard()
                yield f"event: update\ndata: {json.dumps(leaderboard)}\n\n"

            timeout += 1
            if timeout >= 5:
                snapshot = await read_leaderboard()
                yield f"event: snapshot\ndata: {json.dumps(snapshot)}\n\n"
                timeout = 0
    finally:
        await pubsub.unsubscribe("leaderboard_updates")

def inject_order_corruption(order_bytes: bytes,
                          error_rate: float = 0.001) -> bytes:
    """Randomly corrupt 0.1% of incoming orders"""
    if random.random() < error_rate:
        result = bytearray(order_bytes)
        bit_pos = random.randint(0, len(result) * 8 - 1)
        byte_idx = bit_pos // 8
        bit_idx = bit_pos % 8
        result[byte_idx] ^= (1 << bit_idx)
        return bytes(result)
    return order_bytes
\end{lstlisting}

\chapter{Composite Scoring Algorithm}
% ============================================================================

\section{Formula}

\begin{equation}
\text{score} = \frac{\text{TPS}}{\max(\text{p99\_latency\_us}, 0.1)}
\end{equation}

Where:
\begin{itemize}
    \item $\text{TPS}$ = trades per second in rolling window
    \item $\text{p99\_latency\_us}$ = 99th percentile engine latency in microseconds
    \item $\max(\ldots, 0.1)$ = prevents division by zero
\end{itemize}

\section{Derivation}

\subsection{Why TPS (Numerator)?}

\begin{itemize}
    \item Rewards high order submission rates
    \item Incentivizes market participation
    \item Reflects hardware optimization efficiency
\end{itemize}

\subsection{Why P99 Latency (Denominator)?}

\begin{itemize}
    \item Penalizes tail latency
    \item Reflects SLA requirements (production trading)
    \item Avoids mean-chasing behavior
\end{itemize}

\chapter{Architecture Decision Records}
% ============================================================================

\section{ADR-001: WebSocket for Bot-Engine Communication}

\textbf{Decision}: Use WebSocket (RFC 6455) instead of raw TCP

\textbf{Rationale}:
\begin{itemize}
    \item Standard protocol with no custom binary framing
    \item Python \texttt{websockets} library is production-grade
    \item Passes through firewalls/proxies (port 80/443 capable)
    \item Hand-rolled implementation allows latency optimization
\end{itemize}

\textbf{Alternatives Rejected}:
\begin{itemize}
    \item Raw TCP: Lower overhead but no standardization
    \item HTTP/REST: Polling adds unacceptable latency
    \item gRPC: Adds complexity without benefit for this use case
\end{itemize}

\section{ADR-002: Lock-Free MPSC Queue}

\textbf{Decision}: Use lock-free Multi-Producer Single-Consumer queue for order ingress

\textbf{Rationale}:
\begin{itemize}
    \item Many TCPServer connections $\rightarrow$ single MatchingEngine thread
    \item Avoids mutex contention in hot path
    \item Bounded memory via ring buffer
\end{itemize}

\section{ADR-003: Kafka for Trade Durability}

\textbf{Decision}: Publish all trades to Kafka before scoring

\textbf{Rationale}:
\begin{itemize}
    \item Scoring engine failure doesn't lose trades
    \item Enables windowed scoring and replay
    \item Decouples matching from scoring
\end{itemize}

\section{ADR-004: eBPF Kernel Tracing (Future)}

\textbf{Decision}: Optional eBPF-based latency probing (enhancement)

\textbf{Rationale}:
\begin{itemize}
    \item Separates kernel vs. userspace latency contributions
    \item Detects OS scheduling jitter
    \item Non-intrusive (zero userspace overhead)
\end{itemize}

\textbf{Limitation}: Requires Linux kernel 4.4+ with BPF JIT enabled

\section{User Submission Journey}

The complete lifecycle of a contestant submission:

\begin{enumerate}
    \item User selects ZIP file and enters contestant ID
    \item Browser uploads via \texttt{POST /api/v1/submissions/upload}
    \item API extracts and validates ZIP structure
    \item API spawns orchestrator as async subprocess
    \item Orchestrator loads Kubernetes configuration
    \item Creates \texttt{evaluation-sandbox} namespace
    \item Auto-detects language (Python/Rust/Go/C++)
    \item Generates language-specific Dockerfile
    \item Builds container image via Docker
    \item Spawns scoring engine as subprocess
    \item Creates and applies Kubernetes pod
    \item Pod starts, bot begins trading
    \item Engine matches orders, publishes TradeEvents to Kafka
    \item Scoring engine validates and updates leaderboard
    \item Browser receives SSE updates, displays live leaderboard
    \item After 60 seconds, evaluation completes
    \item Pod deleted, scores persist in Redis
\end{enumerate}

\end{lstlisting}

\section{Validation Checks}

\begin{lstlisting}[language=python]
def validate_submission(extracted_dir: str) -> bool:
    checks = [
        (os.path.exists(
            os.path.join(extracted_dir, "sandbox_sdk.py")),
         "sandbox_sdk.py REQUIRED"),

        (os.path.exists(
            os.path.join(extracted_dir, "solution.py")),
         "solution.py REQUIRED"),

        (os.path.getsize(extracted_dir) < 100 * 1024 * 1024,
         "Exceeds 100 MB"),

        (count_files(extracted_dir) < 10000,
         "Too many files (>10000)"),
    ]

    for condition, error_msg in checks:
        if not condition:
            raise ValidationError(error_msg)

    return True
\end{lstlisting}
